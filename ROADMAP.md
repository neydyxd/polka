# Полка: трекер чтения

Пет-проект для тренировки React. Код пишешь ты, я ставлю задачи, рисую макет и ревьюю.

- Макет: [mockup.html](mockup.html) (открой в браузере, все размеры и цвета смотри через DevTools)
- Стек: Vite + React + TypeScript + React Router + TanStack Query + Supabase, формы на react-hook-form + zod
- Данные о книгах: [Open Library API](https://openlibrary.org/developers/api), пользовательские данные: Supabase

## Как работаем

1. Каждый этап делаешь в отдельной ветке `stage-N` и открываешь PR в свой `main`.
2. Кидаешь мне ссылку на PR или путь к папке со словами «ревью этапа N».
3. Я ревьюю как тимлид: баги, что не по-мидловски, что спросят на собесе. Правишь, мержишь, идёшь дальше.
4. Застрял: пиши «подсказка» и что пробовал. Дам направление, а не готовый код.

Правило одно: **не проси у меня код решения.** Иначе проект будет, а навыка нет.

Ориентир по времени: этап за 3–7 вечеров. Не страшно, если дольше.

## Этап 3. Поиск через Open Library

Запрос: `https://openlibrary.org/search.json?q=...&page=1&limit=20&fields=key,title,author_name,cover_i,first_publish_year,number_of_pages_median`
Обложка: `https://covers.openlibrary.org/b/id/{cover_i}-M.jpg`

- [ ] TanStack Query: `QueryClientProvider`, функция запроса в `features/search/api.ts`
- [ ] Типы ответа API описаны руками, без `any`
- [ ] Свой хук `useDebounce` (300 мс), запрос уходит не на каждую букву
- [ ] Строка поиска живёт в URL (`?q=`): обновил страницу, поиск сохранился. Используй `useSearchParams`
- [ ] Отмена устаревших запросов: передай `signal` из TanStack Query в `fetch`
- [ ] Все состояния из макета: загрузка (скелетоны), пусто, ошибка с кнопкой «Повторить»
- [ ] «Показать ещё» через `useInfiniteQuery`
- [ ] Поле ввода не лагает при быстром наборе

**Готово, когда:** быстро печатаешь «выразительный», во вкладке Network один-два запроса, а не десять.

**Почитать:** react.dev, Adding Interactivity целиком. Документация TanStack Query: Queries, Query Keys, Infinite Queries.

**Спросят на собесе:** debounce против throttle, зачем query key, что такое stale time и cache time, race condition при поиске и как её избежать.

## Этап 4. Supabase и авторизация

- [ ] Проект в Supabase (бесплатный тариф). Ключи в `.env.local`, файл в `.gitignore`, в репозитории `.env.example`
- [ ] Таблица `user_books`:
  | поле                                                                              | тип                               |
  | --------------------------------------------------------------------------------- | --------------------------------- |
  | `id`                                                                              | uuid, pk                          |
  | `user_id`                                                                         | uuid, ссылка на `auth.users`      |
  | `ol_key`                                                                          | text (ключ книги из Open Library) |
  | `title`, `author`                                                                 | text                              |
  | `cover_id`                                                                        | int, nullable                     |
  | `pages_total`, `pages_read`                                                       | int                               |
  | `status`                                                                          | enum: `want`, `reading`, `done`   |
  | `rating`                                                                          | int 1–5, nullable                 |
  | `started_at`, `finished_at`, `created_at`                                         | timestamptz                       |
  | Уникальность пары `user_id + ol_key`: одна книга не может попасть на полку дважды |
- [ ] **RLS включён** и политики: пользователь видит и меняет только свои строки (`user_id = auth.uid()`). Без этого любой может прочитать чужие полки
- [ ] Типы из базы: `supabase gen types typescript`
- [ ] Регистрация и вход по email и паролю, экран как в макете, ошибки под полями
- [ ] Сессия в контексте (`AuthProvider`), защищённые маршруты: без входа редирект на `/login`, после входа возврат туда, откуда пришёл
- [ ] Кнопка «Выйти»

**Готово, когда:** второй пользователь не видит книг первого. Проверь это руками в двух браузерах.

**Почитать:** react.dev, Managing State: Passing Data Deeply with Context.

**Спросят на собесе:** где хранить токен и почему, что такое RLS, когда хватит контекста, а когда нужен стейт-менеджер.
